# Original owner records in the BDE connection journal

The explicit research profile `ASCET_BD_CONNECT_REFERENCES=module_owner_records_v1` selects `native_connect_material_v4`. It requires the existing fixed Main connection material, staged executor and isolated `BDE_Tool_Experiments\Trial_*` Module. It does not authorize production connection writes or history execution.

One connection preparation now captures the original full allocated `CTreeSearchObjectRecord` for the Module and `SGTopGraphicsBlockDB` source, plus outgoing/incoming owner records and the explicitly requested reciprocal targets. The native token and original semantic generation bind every receipt. Owner capture independently rereads the complete reference image and requires it to match the finite capture. Raw tails, headers and genuine absence are retained. A later read cannot substitute for original before.

`capture_attached` has an owner after capture path, but real v4 connection application remains gated. That path has not been accepted online. Actual WAL fields are `persistent_owner_records_actual` and `persistent_owner_record_differences`. `bd_diff` derives a compact digest/extent/version/state delta from the complete WAL bytes without live reads. The raw images remain in the journal rather than the agent response. Synthetic journal controls verify this path; they do not certify real editing.

`bd_connect_journal.persistent_owner_inverse_request(log, token, current)` binds a composite owner/reference proposal to one confirmed durable v4 forward. The caller can provide only CURRENT. Both resource plans must pass before any candidate is returned. A changed serialized owner is restored only when its complete CURRENT equals its actual after, or needs no patch when already equal to original before. Overlapping source changes reject the whole proposal. Unchanged owners retain unrelated CURRENT edits. Reference existence transitions use the existing original-bound finite lifecycle planner.

The current native reference leaf writer is limited to the isolated Module/source physical keys. An external reciprocal write rejects the composite request; v4 capture cannot extend that writer's authority. There is no byte-wise merge of an overlapping serialized source graph. There is no native dispatch, automatic retry or history upgrade from this planner.

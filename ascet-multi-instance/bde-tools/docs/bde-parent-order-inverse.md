## Implementation

`bde_structure_edit.st` now captures the actual `orderCollection` reference along
with the before/after member arrays for `disconnect_data` and `delete_node`.
The direct current scope parent must still be the original parent. The unchanged
selected graph closure, diagram, native epoch and hierarchy guards remain required.

The fixed `bde_parent_order_inverse.st` helper uses the existing identity-based
three-way order kernel. It accepts only insertions of exact retained originals;
current members must still belong to the exact parent. It verifies original
deletion slots, the complete removed roster, detached managers and saved edge
connection-point identities/registrations. Conflicting same-gap additions,
reordered original anchors, changed parent ownership and missing collection
bindings refuse before execution.

Original tuples retain their original indices. A separate insertion-position map
controls restoration into CURRENT. For example, the native probe's original
member 2 was deleted from `[1,2,3,4,5,6,7]`. After an independent member 8 was
inserted before member 1, the helper produces `[8,1,2,3,4,5,6,7]` and restores the
original member at position 3. It also preserves an independently removed member
4 rather than recreating it.

The prepared helper rechecks the complete CURRENT order, actual collection/member
ownership, detached identities, original tuples and generated position map. The
dispatcher rechecks the helper before its first setter, restores originals in
the generated insertion order, and compares the actual merged order both before
and after `storeToCache`. It does not replace a graph or the old registry.

The C# bridge binds only embedded fixed helpers when
`ASCET_BD_ORDER_INVERSE_EXPERIMENTAL=1`. Default behavior remains strict. Older
records without a saved collection reference cannot use this experimental path.
The flag does not bypass sandbox, pending-operation or restoration protections.
Do not enable it as accepted model functionality based on these helper trials.
